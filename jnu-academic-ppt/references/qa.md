# 预测提问清单

交付时出两份，**都不额外建文件**：

1. **对话里给完整版，这是主交付**——用户当场能看见、能继续追问，也不依赖 PowerPoint 版本。
2. **同时写进结尾页的 `notes` 作为便携备份**——上台前可以在演讲者视图中查看。备注版精简到 600 字以内，一条一行。

不要只写备注。WPS、手机预览和导出的 PDF 可能隐藏备注；用户明确要求不写备注时，只保留对话版。

组会给 5–8 条，答辩给 8–12 条。每条三段式：

```
Q：可能被问什么
A：建议怎么答（一两句，给要点不给逐字稿）
→ 你现在答得上来吗？ / 需要先补什么
```

最后一段是关键——它的作用不是替用户回答，是**告诉用户哪几个洞还没补上**。

使用本地引擎时，优先在 `deck.json` 顶层写结构化 `qa` 数组。构建器会把精简版自动合并进结尾页备注（按整题取舍，超出 600 字的题在备注里注明「见对话」）；交付时仍要把完整版发在对话中。

```jsonc
"qa": [
  {"slide": 7, "question": "为什么只跑一个随机种子？",
   "answer": "说明当前结果只能作为初步趋势，并给出补跑计划。",
   "gap": "需补充另外两个种子的结果"}
]
```

## 从 PPT 里推提问点

按这个顺序扫一遍自己刚做的 deck，每命中一条就是一个问题：

| 扫描点 | 会被问什么 |
|---|---|
| 任何一个数字 | 怎么测的？样本量多少？跑了几次？方差多大？ |
| 任何一个对比 | 基线是怎么选的？公平吗？超参调过没有？ |
| 任何「我们的方法更好」 | 好在哪？统计显著吗？换个数据集还成立吗？ |
| 任何一张图 | 横纵轴是什么？单位？这条线为什么会掉？ |
| 用了别人的方法/代码 | 是原版还是自己复现的？复现对得上吗？ |
| 说了「还在跑 / 待补」 | 什么时候能出？出不来的话 plan B 是什么？ |
| 说了「试了没用」 | 为什么没用？是方法不行还是没调好？ |
| 提了创新点 | 和最接近的那篇工作到底差在哪？ |
| 有卡点求助 | 你自己想过哪些方案？各自的问题是什么？ |
| 下一步计划 | 为什么先做这个？优先级怎么排的？ |
| 整份 PPT 没提的 | 数据从哪来？有没有伦理/合规问题？（医疗、人脸、爬虫类必问） |

## 不同场景的高频问题

### 组会
导师最常问的三类：
1. **「这个数你信吗」** —— 复现性、随机种子、有没有跑多次
2. **「为什么是这个方向」** —— 你排除了哪些路，理由是什么
3. **「下周能出什么」** —— 要一个具体的可交付物，不是「继续优化」

### 开题 / 中期
1. 这个问题为什么值得做？没人做过还是做不好？
2. 技术路线里风险最大的是哪一步？做不出来怎么办？
3. 工作量够不够一篇学位论文？
4. 数据怎么来？够不够？

### 毕业答辩
1. 创新点到底是什么？（必问，要能用一句话说清）
2. 和最相近的那篇工作比，你的增量在哪？
3. 实验为什么只做了这几个数据集？
4. 局限性你自己怎么看？
5. 论文第 X 页那个公式/结论怎么推的？

### 竞赛答辩
1. 商业模式 / 落地路径是什么？
2. 竞品有哪些？你的壁垒是什么？
3. 团队为什么能做成这件事？
4. 现在做到什么程度？有真实用户/数据吗？

## 写清单的原则

- **优先列答不上来的**。已经在 PPT 里写清楚的问题价值不大，
  真正有用的是「你这页留了个洞，很可能被戳」
- **具体到页**。写「P7 的 78.2% 会被问怎么测的」，不要写「注意数据问题」
- **不要替用户编答案**。建议怎么答只给方向（「强调三种子方差 ±0.2」），
  用户没告诉你的事实不要替他编
- **标出真空区**。如果某个必问问题用户完全没提供信息，明确说
  「这条你得自己想，我手上没有材料」
