# 配图：从哪来、什么能画、什么不能画

PPT 里的图按来源分三类，规矩完全不同。

| 来源 | 怎么拿 | 图注怎么写 |
|---|---|---|
| **原文的图表** | 从 PDF 里裁 | `图 3　注意力可视化（Vaswani et al., 2017, Fig. 3）` |
| **自己跑出来的** | 自己的实验脚本 | `图 5　本实验结果，n=3 seeds` |
| **AI 生成的示意图** | `scripts/gen_figure.py` | `示意图（AI 生成）` —— **必须标注** |

## 先选生成方式

1. 宿主有原生图片生成或编辑工具时优先使用。Codex 使用 image generation 工具；Claude 使用当前会话实际提供的生图工具。
2. 宿主没有原生工具、但用户已配置 OpenAI API 时，使用 `scripts/gen_figure.py`。
3. 两者都不可用时，使用用户提供的真实素材或明确说明缺图；不要在最终 PPT 中留下占位框。

原生工具和 API 脚本遵守同一套证据与标注规则。不要为了调用脚本而要求已经能用原生生图工具的用户再次配置 API key。

---

## 一条不可越界的线

**AI 生成的图只能画「概念」，绝对不能画「数据」。**

✅ 可以让它画：
- 技术路线图、系统框图、模块关系图
- 流程示意（数据怎么流、信息怎么传）
- 概念类比插画（用来解释一个抽象机制）
- 封面/章节页的装饰图形

❌ 绝对不能让它画：
- 实验结果图、性能曲线、柱状图、散点图、混淆矩阵
- 任何带具体数字、坐标轴、数据点的图
- 任何会被听众当成「实验证据」的东西

理由很直接：**画一张看起来像结果的图，等于伪造实验证据**。
组会上被问一句「这数哪来的」就穿帮，答辩上更严重。

真要画数据图，用真实数据自己画（matplotlib / Excel 都行），
或者直接截原文的图并注明出处。

`gen_figure.py` 的 prompt 里已经硬编码了
`Do NOT invent any numbers, axes, data points, charts, or plotted curves`，
但这只是第二道闸，**第一道闸是你别提这种需求**。

## 怎么用

```bash
# 先确认接口配好了
python <SKILL_DIR>/scripts/gen_figure.py --check

# 生成一张跟主题同色系的示意图
python <SKILL_DIR>/scripts/gen_figure.py \
  "一张解释自注意力的示意图：一行方块代表序列中的 token，中间某个 token 用箭头同时连向所有其他 token，箭头粗细代表权重大小；旁边对照画一条 RNN 的链式结构，信息要逐个节点传递" \
  --out "素材/self_attn_vs_rnn.png" --theme jnu-teal --size 1536x1024
```

生成后会在旁边留一个 `<图名>.png.json` 记录 prompt 和模型，交付时能说清出处。

deck.json 里照常引用，**caption 必须标注**：

```jsonc
{"layout": "image-text", "title": "自注意力把任意两个位置的距离压到一步",
 "image": "素材/self_attn_vs_rnn.png",
 "caption": "示意图（AI 生成），非实验结果",
 "bullets": ["..."]}
```

## 配置

任选其一（`.openai.json` 已在 `.gitignore` 里，不会被提交）：

```bash
set OPENAI_API_KEY=sk-...
```

```jsonc
// <skill根目录>/.openai.json
{
  "api_key": "sk-...",
  "model": "gpt-image-2.5-flare", // 可选；也可用 OPENAI_IMAGE_MODEL 覆盖
  "base_url": "https://xxx/v1"   // 可选，国内走中转时填
}
```

没配 key 时脚本会明确报错并告诉你怎么配，**不会静默跳过**。
接口不通时也一样：deck.json 里引用了不存在的图，构建会画占位框 + 报警告，
不会悄悄出一份缺图的 PPT。

## 写 prompt 的经验

- **描述结构，不描述数据**。写「三个模块从左到右串联，中间有反馈箭头回到第一个」，
  不要写「展示准确率从 71% 提升到 78%」
- **文字标签越少越好**。生成模型的中文字形经常是坏的，英文也常拼错。
  标签宁可留空，后期在 PowerPoint 里用文本框自己加——反正产物是可编辑的
- **指定画风**，脚本已经默认加了「扁平、细线、大留白、无 3D、无渐变、白底」
- **带上 `--theme`**，脚本会把该主题的主色塞进 prompt，图和 PPT 同色系
- 一次不满意就换个说法重跑，比在 PowerPoint 里手动改快

## 出处记录

无论使用宿主原生工具还是 API，都记录：生成工具/模型（能取得时）、原始提示词、日期、用途和是否编辑过参考图。API 脚本会自动写 `<图片名>.json`；原生工具生成时由 Agent 在同目录补同样格式的记录，或在 PPT 备注中写清。
