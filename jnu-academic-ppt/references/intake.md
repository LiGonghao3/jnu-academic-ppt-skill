# 内容采集协议

组会 PPT 真正的成本不在排版，在**回忆和整理**。
这份协议的目标是：让用户用最口语、最零散的方式把东西吐出来，整理由你做。

---

## 四个入口怎么处理

### 入口 1：周记流水账（最省事，优先推荐）

用户给一个 md 文件（模板见 `assets/weekly-template.md`）。逐行读，按这四类归位：

- `进展` —— 做成了什么、跑通了什么、写完了什么
- `证据` —— 数字、图、表、实验结果、对比
- `卡点` —— 卡住的、没搞定的、需要资源或决策的
- `下一步` —— 下周要干的

流水账一定是乱的。你的活是**合并同类项、按因果串起来、补出结论**。
比如三行「周一跑了 baseline 71.4」「周二试了 LARS 没用」「周三发现是裁剪太狠」
应该合成一页，标题写「掉点来自数据增强，不是模型」。

读完必须追问补缺（见下方清单），**不要读完就直接生成**。

### 入口 2：素材文件夹

用户给一个文件夹路径。扫描并分类：

| 文件类型 | 怎么用 | 工具 |
|---|---|---|
| 实验结果图、截图 (png/jpg) | 当证据放进 `image-text` / `image-full` | 直接引用路径 |
| PDF（论文、报告） | 抽正文和原图 | 使用宿主提供的 PDF 工具；没有时再用本地 PDF 库 |
| md / txt 笔记 | 当流水账读 | 直接读 |
| xlsx / csv | 抽成 `table` 或 `kpi` | 读取后自己整理 |
| 代码 / commit log | 转成「做了什么」的进展条目 | 读取后概括 |

**扫描完要把清单念给用户听**，并问：哪些是这次要讲的重点、哪些只是顺手存的。
不要把文件夹里所有东西都塞进 PPT。

图片引用规则：`deck.json` 里写相对路径，构建时用 `--assets <文件夹>` 指定根目录；
找不到图会画占位框 + 报警告，不会静默跳过。

### 入口 3：单篇论文

用户给一个 PDF。按 `问题 → 方法 → 证据 → 局限 → 启发` 组织。要点：

- **图表一律用原文的**，不要自己重画重编数据
- 每张图注明出处（Fig.3 / Table 2）
- 公式：能用文字说清楚的就用文字；必须放公式时截图原文，别手打 LaTeX 转图
- 最后一页必须是「**对我们组的启发**」——这是文献汇报唯一不可替代的部分，
  不写这个就只是念论文摘要

追问：为什么选这篇？和我们在做的事哪里搭得上？你信它的结论吗？

### 入口 4：什么都没有，口头说

最常见，也最需要你主动。直接进追问清单。

## 追问清单（按场景选，一次问 2–4 个）

用户已经给足材料时，不要机械地把清单问一遍。先复述已知信息，只问会改变叙事、证据或交付格式的缺口。

### 每周组会 / 进展汇报

第一组（必问）：
1. 这周最主要在推哪件事？一句话说
2. 推到什么程度了？跑通了 / 半成品 / 还在查问题
3. 有没有具体数字或结果图？（准确率、耗时、条数、截图都算）

第二组：
4. 有什么卡住了？想在会上问谁、问什么？
5. 有没有试了但没成的？为什么没成？
6. 下周打算干什么？

第三组（可选，有就问）：
7. 这周读了什么文章 / 参加了什么比赛 / 听了什么报告？值得跟大家提一句的？
8. 有没有踩到坑、想提醒同门的？

> **「什么都可以讲」是这个场景的特点**：比赛、读的文章、甚至闲聊里冒出的想法，
> 都可以进「本周其他」一章。不要因为不是主线就砍掉——组会本来就是同步信息的。

### 论文精读

1. 这篇解决什么问题？之前大家怎么做的、差在哪？
2. 它的核心做法是什么？一句话
3. 最能说服你的是哪张图 / 哪个实验？
4. 你觉得哪里不靠谱、或者没说清楚？
5. 跟我们组在做的事有什么关系？能借什么？

### 开题 / 中期 / 毕业答辩

1. 题目是什么？研究对象和范围
2. 为什么值得做？（现实需求 + 学术空白各一句）
3. 技术路线分几步？每步产出什么？
4. 已经做到哪了？有什么阶段性结果？
5. 创新点自己怎么概括？（一般 2–3 条）
6. 有什么局限、你预计老师会挑哪里？
7. 导师、学院、专业、答辩日期

### 竞赛答辩 / 路演

1. 比赛名称、赛道、答辩时长、评委构成
2. 解决什么痛点？谁在痛？痛到什么程度（最好有数）
3. 方案是什么？和现有做法比强在哪
4. 做到什么程度了？（原型 / 落地 / 有用户 / 有数据）
5. 团队分工、有什么背书（导师、奖项、专利、合作方）
6. 评分标准里哪几项分最重？

## 整理原则

### 把流水账变成汇报

1. **先找主线**。一周再杂也有一件最重要的事，它占 50% 以上篇幅
2. **合并同类项**。同一件事的三天进展合成一页，不要按日期排
3. **补出结论**。每页问自己「所以呢？」，答案就是标题
4. **杂事集中放**。比赛、读文章、听报告这类合成一章「本周其他」，
   每件 1–2 行，不要每件单独开页
5. **闲聊也能讲**。组会里的「唠嗑」常常是最有价值的信息同步，
   放进「其他」或「想法」里，写成一句有信息量的话就行

### 不许做的事

- **不许编数字**。用户没给的准确率、耗时、样本量，一律留空或写「待补」，
  然后在交付时明确告诉用户哪几页需要他自己填
- **不许编结论**。用户说「还在跑」，就写「还在跑」，不要写成「初步验证有效」
- **不许为了凑版式加内容**。三个卡点就三张卡片，不要凑成四张
- **不许把失败包装成成功**。「试了没用」照实写，这是组会的正常内容

### 信息不足时

如果追问完发现内容实在撑不起一份 PPT（比如这周确实没干什么），
**直接告诉用户**，并给两个选项：
- 做一份 5–6 页的极简版（主线 + 卡点 + 下周）
- 或者把范围扩到两周

不要靠注水把 6 页撑成 15 页。
